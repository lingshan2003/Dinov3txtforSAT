# SAT 恢复多图与多正例实验审阅

日期：2026-10-05。来源：用户上传的 `/Users/wangyue/Downloads/sat_multi_positive_seed11_reports.tar.gz`。

## 1. 当前结论

**在 seed11、1710 optimizer step、相同图片曝光预算下，rotate 的三套评测 mean Recall 都略高于历史 adapter+LoRA；当前均匀多正例版本没有超过它。**

rotate 通过每次访问 caption 组时轮换图片，恢复视觉多样性，同时每个物理 batch 保持不同 caption。
这为不再永久固定一图提供了初步支持。不过其原 SkyScript 双向 R@1 都下降，且提升幅度较小，不能声称全面或显著改善。

多正例与屏蔽对照的每批不同 caption 数从 16 降到平均 11.33，改变了负例多样性、caption 访问次数和查询权重。
本轮只能评价这套完整配方，不能据此否定多正例关系本身。maskpos 相对 multipos 的四项汇总指标均较高，是同一采样方案下更有解释力的 loss 对照。

报告包含数据审计、三组新训练的配置/日志/优化器/来源/summary/validation、历史基线元数据、24 份检索 JSON 和检索日志。
新训练配置与当前仓库对应配置一致，报告项目版本为 `5297eb83f7edc638aa6d640f1ad3989f46bbcd1f`。

恢复后的候选池共 370,317 张图，保留原 40,550 个完整 caption 组及原代表图：

| split | 图片 | caption 组 | 单图组 | 最大组 |
| --- | ---: | ---: | ---: | ---: |
| train | 337,199 | 36,495 | 20,437 | 2,777 |
| val | 33,118 | 4,055 | 2,276 | 1,228 |

分组按完整文本做空白归一化、casefold，额外图片沿用该组原 split。
审计记录缺图、caption 组交叉、路径交叉、sample ID 交叉均为 0，全部原代表图保留。
这些是元数据检查；新增图片尚没有像素、地理邻近或语义独立性审计。
训练组中 56.00% 为单图组，组大小分布很不均衡，因此恢复多图不等于所有 caption 都能组成两个正例。

所有实验使用冻结 SAT ViT-L/16 backbone、冻结官方 vision head，训练 residual adapter 和完整文本侧 LoRA（含 projection）。

可训练参数共 5,013,760：adapter 1,054,976、文本 backbone LoRA 3,932,160、projection LoRA 26,624。
这里 projection 的原权重被冻结，更新的是其 LoRA 分支。

共同条件：seed11、图片 224、文本 global77、BF16、学习率 1e-4、cosine 日程、warmup171、queue0、无数据增强。
物理 batch16、梯度累计4、1710 optimizer step，共 6840 个物理 batch、109,440 次图片曝光。
梯度累计扩大更新所累计的样本数，**不会把四个独立 16×16 loss 的对比候选合并成一个 64×64 loss**。

| 编号 | 方法 | 训练数据与目标 |
| --- | --- | --- |
| A | 原 adapter+LoRA | 历史 unique-caption 代表图训练，单正例，复用已完成的三轮实验 |
| B | rotate | 同 caption 组跨访问轮换图片，每批每组一图，单正例 |
| C | multipos | 每组最多两图，保留单图组，均匀多正例交叉熵 |

C/D 的组不会跨物理 batch，剩一个位置时可只取一图。两组采样诊断完全一致。
D 用于检验是否需要主动拉近多个正例；它不是把这些已知正例继续当负例的对照。

## 3. 训练完整性与覆盖

三组均 `completed=true`，没有 resume、跳过更新、非有限 loss 或梯度。
日志每 10 step 记录，共 171 条；验证为 0/200/400/600/800/1000/1200/1400/1600/1710，共 10 次。
共同 step0 验证 loss 为 3.864123，三组验证 loss 均连续下降，best 都在 1710。
预裁剪梯度范数较大，但已按配置裁剪为 max norm1，未发现因此失效的报告证据。

| --- | ---: | ---: | ---: | ---: | ---: |
| A 原基线 | 0.902339 | 固定代表图 | 不适用 | 16 | 原代表图三轮 |
| B rotate | 0.864865 | 63,469 | 18.82% | 16 | 3 |

三组峰值 CUDA allocated 均约 5.68 GiB；日志训练窗口累计时间约 25.4 分钟，不含完整启动和三套检索耗时。
B 验证 loss 比 A 低 4.15%。但 C/D loss 也低于 A，却没有一致提高完整检索指标：固定小 batch 的验证 loss 不是全局检索效果的充分代理。

**本轮不是恢复后的 337,199 张训练图完整训练三遍。** 1710step 保持原图片曝光预算，轮换也只能覆盖有限图片。
group epoch 是对组的访问轮次；大组每轮只消费一至两张图。增加覆盖需要另定训练日程，不能仅凭终点下降就断言延长一定提高检索。
cosine 日程到终点已将学习率降至接近 0，因此应区分当前日程末期变平和模型潜力耗尽。

## 4. 完整检索结果

下表均为百分数；mean Recall 是双向 R@1/5/10 共六个指标的算术均值。

| 方法 | SkyScript 原 unique | SkyScript 多图，按图平均 | SkyScript 多图，按组均衡 | RSICD-val |
| --- | ---: | ---: | ---: | ---: |
| A 原 adapter+LoRA | 10.8837 | 8.4961 | 9.0543 | 7.0445 |
| **B rotate** | **11.0974** | **8.9324** | **9.3260** | **7.1877** |
| C multipos | 10.3124 | 8.1190 | 8.6210 | 6.7093 |
| D maskpos | 10.6658 | 8.8512 | 8.8518 | 7.0262 |
| B − A，百分点 | +0.2137 | +0.4362 | +0.2717 | +0.1432 |

原 unique 候选池为 4055 图/4055 文；多图候选池为 33,118 图/4055 文；RSICD-val 为 1094 图/5470 文。
新增多图评测使用明确的 caption 组正例集合，文本候选每组去重一次。
R@K 是查询的前 K 个候选中**至少命中一个已知正例**的比例，不是检回所有正例的比例。
一条文本对应 100 张正例图时，前五名命中其中一张即计该查询 R@5 成功，并不要求全部 100 张进入前五名。

多图按图平均版本的图→文指标让每张图等权；大组因此贡献更多查询。
按组均衡版本先在组内平均图→文命中率，再对 4055 组等权平均，与本来就每组一个文本查询的文→图三项合并。
D 的按图均值高于 A，按组均衡值却低于 A，说明结论对组大小权重敏感，不能只选改善的一列宣称所有描述整体提高。
不同候选池的绝对数值不可直接用来判断恢复多图导致了退化；应在同一池内比较 A/B/C/D。

## 5. 为什么当前多正例没有占优

以下是结合代码与诊断提出的机制解释和待验证假设，不是已完成的因果证明。

**第一，batch 的不同 caption 减少。** B 每批有 16 个不同 caption，C/D 平均 11.3273 个。
C/D 共 45,518 个查询只有一个正例，63,922 个查询有两个正例；总计 109,440 个图片查询。
对应 caption 组访问次数为 45,518 + 63,922/2 = 77,479，较 B 的 109,440 次少 29.20%。
平均每查询正例 1.5841 个；每批同组非对角正例 9.3453 对。
多正例存在真实训练信号，但同一图片预算内，它消耗了本可用于展示另一描述的 batch 位置。
梯度累计没有恢复每次 softmax 中不同描述的数量，因此 B/C 对照混合了正例处理和候选多样性的差异。

**第二，目前 loss 仍是方形配对矩阵，文本重复出现。** 两张图配同一个 canonical caption 时，它会作为两行文本和两列文本候选重复编码。
图→文的正例是两个相同文本副本；文→图则是两个真实不同图片。
均匀多正例 loss 要求向所有已知正例分配概率，而 maskpos 保留配对目标、排除其余同组正例。
二者都避免把该组已知正例当负例，但优化压力不同。
同组重复文本还改变了其他组 softmax 分母中的组权重；按图片行平均让本批有两张图的组获得比单图组更多权重。
这些是当前配方的明确数学行为，报告没有显示实现偏离配置的代码错误。

**第三，caption 关系正确不等于描述细粒度足够。** 数据中存在非常大的同文组，完整候选池中的 `building.` 就对应 2777 张图。
恢复这些图可以增加外观多样性，但文本本身未提供区分具体图片的属性。
均匀目标对两张差异大的图同时施加强配对约束，是否有利于更细描述的泛化，需要按 caption 信息量/组大小分层检索及查看样例。
不能仅凭本轮指标断言发生标签噪声，也不能把所有同类物体自动合并为同一正例组。

C/D 共用采样，D 的四列 MR 都高于 C，因此当前结果支持优先检查均匀目标及重复文本权重。
不过没有“同采样但错误地保留假负例”的一对一对照，不能量化修正假负例相对于未修正的独立收益。

## 6. 下一步建议

1. **先保留 B 为新候选，并复现它对 A 的改善。** 使用 seed23/47、相同输入协议和 1710step 日程，同时检查 MR 和双向 R@1。
   历史 seed23/47 复现是否已完成、是否可直接用作 A，要以其实际报告为准；当前只收到本轮 seed11 包。
2. **多正例下一版先解决文本重复和不同 caption 数量。** 可固定每批 16 个不同组，每组一至两图、每个文本只编码一次，形成“多图片×唯一文本”矩形相似度矩阵。
   图→文只有一个正确 caption 组；文→图保留同组图片正例集合，明确选择均匀目标或其他正例聚合目标，并在图→文方向明确是否按组均衡查询权重。
   预计每批约 23 张图，实际应测量；这会增加图片曝光/计算，必须配匹配曝光或计算的对照，不能继续宣称所有变量都与当前 B 等价。
3. **覆盖量和队列作为后续独立轴。** 在采样/权重清楚后，从共同初始化使用更长 cosine 日程评估覆盖量，不直接把当前末期近零 LR 的 run 接着跑来判断长期潜力。
   queue0 和无增强暂保持为对照条件；扩大队列不能直接解决本轮重复描述和组权重问题。
4. **区分 checkpoint 选择指标与研究评测指标。** 当前 best 由旧 unique-val 小 batch loss 选择；本轮都在终点，因此没有证据判断中间 step 的全局检索是否更好。
   后续可在少量预定节点记录全局 MR/R@1，事先明确 best 选择规则并保持固定 checkpoint 数量。

本次仅完成报告审阅和状态记录，没有修改训练配方或启动新训练。
