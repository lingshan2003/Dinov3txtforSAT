# 当前模型、数据与评价到底回答什么问题

日期：2026-10-08。核对当前Web联合配置、模型封装、训练目标、检索实现、三seed报告、本地SkyScript CSV与RSICD标注。未启动训练或修改评价协议，未重新计算SHA256。

## 1. 能力与当前已验证任务

当前为双编码器：RGB图像经冻结DINOv3 ViT-L/16、冻结原生两层视觉Transformer head形成2048维全局表示，再经过可训练残差adapter；文本经24层文本Transformer及projection形成同维表示，原参数冻结、LoRA更新。最终使用归一化向量点积排序。

原生结构、2048维、两层视觉head和77-token文本上下文见[Meta官方构造代码](https://github.com/facebookresearch/dinov3/blob/main/dinov3/hub/dinotxt.py)。项目adapter作用于最终全局向量，未作用于patch tokens。

| 工作 | 当前状态 | 解释 |
| --- | --- | --- |
| 文本找遥感图片 | 核心、已评价 | 查询句与图库图片分别编码，按相似度返回前K张 |
| 图片找描述 | 核心、已评价 | 在给定文本候选池内排序，不生成新句子 |
| 文本原型驱动的场景分类 | 可实现，项目有历史EuroSAT入口 | 把类别转为文本，比较相似度；最近六组检索报告未验证此任务增益 |
| 图像相似性检索 | 可使用向量实现 | 当前没有独立任务评价，不能从图文结果推断必然改善 |
| 开放词汇局部定位/分割 | 原生patch特征有研究入口 | 当前全局adapter无局部监督，无独立局部能力增益证据 |
| Caption生成、VQA、多轮对话 | 当前无对应输出头或训练目标 | 文本encoder提供表示，不是生成decoder |
| 多光谱、SAR、时序变化检测 | 当前流程未支持其专用输入与监督 | 实现将图像转RGB并缩放至224×224，不能以“遥感”概括全部模态 |

视觉骨干的原始特征保持不变；最终经过adapter的图像向量及文本表示发生变化。检索改善说明跨模态排序改善，不直接说明骨干识别新物体或精确计数能力改善。

## 2. SkyScript监督来源与实际使用版本

SkyScript将OSM语义与遥感图像连接。官方提供规则生成的文本、聚焦对象与周边对象描述，以及后续ChatGPT自然语言改写版本；top30表示图文相似度筛选，不是人工正确率保证。见[官方数据说明](https://github.com/wangzhecheng/SkyScript#download-captions)。

当前使用根目录`SkyScript_train_top30pct_filtered_by_CLIP_laion_RS_language_polished.csv`，只取images2/images3。该本地文件共1,518,888行，选中370,317张候选图、40,550个规范化caption组。不是整个SkyScript，不是官方SkyScript test。

实际字段为filepath/title_raw/title。title_raw是内容句，不是原始OSM标签；本地示例：

- title_raw：`Commercial building used for cars.`
- title：`An aerial image. It shows: Commercial building used for cars.`

当前实验使用title_raw，不使用统一前缀或另一CSV的title_multi_objects。

训练为337,199图、36,495caption组；验证全部为33,118图、4,055组。图片恢复保持原caption组边界，训练与验证规范化完整caption不重合。该90/10比例按组计算，不是严格按图片计算。图像统计及组关系来自现有报告和准备工具；本地不持有服务器完整split清单。

完整caption不重合不等于所有词汇/物体类别未见，也不等于地理、邻接区域、同一OSM对象或跨传感器严格独立。原代表图曾做精确文件/像素重叠检查，不能把该结果自动扩写为恢复全部图片后的近重复与地理审计。

监督主要提供地物类别、用途及部分属性/关系。合理预期是改善这些概念与图像的匹配，但当前只有汇总检索证据，尚未按属性、对象、长度或关系类型验证收益。

短句不能充分监督复杂场景布局、精确数量或细粒度语言组合；仅靠同文负例屏蔽也不能解决同义caption和近重复图像。OSM功能标签、微小目标、历史标签及生成式改写可能与实际可见内容不完全一致。这些是应抽样审核的监督风险，不是已判定每条记录错误。

## 4. 当前训练学的是什么

使用有监督图文对比适配：提高标注配对图文相似度、降低其他batch候选的相似度。当前目标mask_same_caption屏蔽同组非对角项，保留配对目标；它与把所有同组图片显式拉近的均匀multi-positive目标不同。

每次物理batch16，queue0；梯度累计4次再更新，不把四批拼成64候选的对比softmax。一图片epoch完整曝光337,199图，未启用随机裁剪。

对比loss反映batch内竞争，完整检索面对数千/数万候选；低batch loss不等于全库检索接近完成，也不能单独判断模型上限。

## 5. 三种评价池的任务与正例

| 评价池 | 图像/文本 | 正例定义 | 回答的问题 |
| --- | --- | --- | --- |
| SkyScript unique-val | 4,055 / 4,055 | 固定代表图与该caption一对一 | 未进入训练的caption组在共同检索尺度上是否改善 |
| SkyScript group-val | 33,118 / 4,055 | 每个caption对应其组内全部图片 | 多图视觉实例下，至少找回一个标注正例是否改善 |
| RSICD-val | 1,094 / 5,470 | 图→文为该图5条caption；文→图为标注所属1张图片 | 换数据来源/描述风格后，外部遥感检索变化怎样 |

unique与group共享4,055验证caption组，不能当作两份独立测试。RSICD不用于本轮反向传播，但已经用于开发判断，属于外部开发验证，不是未触碰的最终test。

R@K为至少一个标注正例进入前K的查询比例。group的文本查询若有100张正例，命中其中任何1张即成功，不要求找全100张。按组均衡统计对图→文先组内平均、再各组等权，避免图片大组支配结果；文→图本来就是每组一个查询。

MR为双向R@1/R@5/R@10六项平均。17.78% MR不是17.78%的top1分类正确率；当前联合unique图→文/文→图R@1均值约5.19%/5.71%。不同候选池与正例数会改变任务难度，不能直接用SkyScript与RSICD的MR大小推断哪个领域更容易。

## 6. RSICD数据与重复标注的新发现

RSICD原本服务图像caption生成研究，公开数据含10,921张224×224图像，每图5条描述，来自Google Earth、Baidu Map、MapABC、Tianditu等。这里复用其图文标注评价检索，没有训练生成器。见[数据作者仓库](https://github.com/201528014227051/RSICD_optimal)。

本地annotations_rsicd.rar的dataset_rsicd.json划分为train8,734、val1,094、test1,093。不同论文可能另切split，不能自动视为同一协议。

本地val新统计：

- 5,470条caption记录、规范化不同文本2,313条；
- 998/1,094张图的5条描述中有组内重复，不是五条独立表达；
- 209条规范化文本出现在多张图片的标注中；
- 按caption记录空白切分平均9.94词、中位9、P95为15，包含标点。

上述来自本地原始标注，当前报告池计数一致，但服务器完整manifest未随报告提供，因此尚未逐条确认服务器文本与本地标注完全一致。

现有RSICD评测按image_id归属定义正例，不根据相同文本跨图合并：重复文本作为不同候选记录保留，文本查询也按记录计权。若同文对应多张图片，相同文本向量无法区分这些标注归属，完全同分按候选索引确定顺序；语义合理但未在该记录正例集合内的结果仍可能被判错。

这限制绝对指标的语义解释，但不抹去固定池、固定协议下已观察的方法差异。不能直接宣布低分全由重复导致，也不能保证换协议后方法排序不变。若补充同文集合评价，应先核对服务器清单、保留旧协议结果并另列辅助指标，避免覆盖历史对照。更广义语义等价需人工或独立标注支持。

## 7. 当前成果的合适表述及后续分析

当前成果是：在偏高分辨率、OSM派生短描述的SkyScript子集上，用有限参数适配提高未训练caption组的全局双向检索；对另一个图文描述数据集RSICD测量迁移变化。不能称“全面提高遥感理解”或“恢复通用自然图像能力”；RSICD仍是遥感，不是所有通用能力的代理。

报告值得加入的分析：按caption长度、对象/属性/关系、来源代码和caption组大小分别报告查询表现；抽样审阅topK中未命中但语义合理的结果；明确功能标签可见性；新增地理独立/未用于开发的评测前冻结协议。上述均为后续建议，本次未新增训练、GPU评测或局部能力结论。
